# Avis V3.1 Phase 0 Audit

Avis V3.1 focuses on hardening the existing V3 architecture. This audit captures
the baseline support posture before deeper integration work continues.

## Core Findings

- Avis already models ecosystem, framework, package manager, capability,
  integration trust, ChangePlans, verification, doctor, repair, and project state.
- Integration trust currently answers who vouches for an integration, but not how
  deeply Avis can set it up.
- Dependency-only integrations are common, including several official or verified
  integrations. They must be presented as install-level support.
- Configured integrations can create files or update project configuration, but
  should not be called managed until transactional apply, ownership tracking,
  drift-aware repair, and rollback behavior are stronger.
- Next.js Auth route generation had a known layout-sensitive import issue.
- Fastify was detectable by the Node detector but missing from the framework
  catalog.
- The root package did not expose a lint command.

## Support Terms

- `install`: Avis can install the native dependency for a compatible project.
- `configure`: Avis can install and create or update meaningful project files,
  environment examples, or framework configuration.
- `managed`: Avis can install, configure, verify, diagnose drift, and repair
  safely. V3.1 should reserve this label for integrations with the necessary
  safety machinery and tests.

Trust is independent from setup maturity. An official integration can still be
install-only, and a local integration can declare the setup depth it provides.

## Current Tier 1 Posture

| Framework | Current posture | Notes |
| --- | --- | --- |
| Next.js | configure | Auth.js creates config, route, and env example. Managed status is blocked on deeper repair and rollback. |
| Django | configure | Django REST Framework and CORS integrations update settings and verify drift. Managed status is blocked on transactional safety. |
| Laravel | configure | Pest creates starter testing files. Sanctum remains install-level. |
| Flutter | configure | Riverpod and GoRouter create starter modules. Managed status is blocked on stronger drift repair. |

## Phase 1 Blockers

- Fix generated Next.js Auth route imports for root `app/` and `src/app/`.
- Catalog Fastify anywhere Avis can detect it.
- Add catalog validation so capability defaults, integration capability
  references, framework references, package manager references, and detectable
  framework coverage cannot drift silently.
- Add a root lint command and include it in release checks.

## Phase 2 Blockers

- Add setup maturity to the manifest type.
- Require setup maturity in manifest validation and custom integration parsing.
- Surface setup maturity in CLI output, generated registry docs, and
  recommendation reasons.
- Backfill built-in integrations conservatively:
  - dependency-only wrappers default to `install`
  - file/config generating planners declare `configure`
  - no current built-in integration is promoted to `managed`

## Follow-up Risk Closure

- File mutations now roll back after failed applies when the file still matches
  the content Avis wrote during that run.
- Dependency additions now roll back only for packages Avis can prove were absent
  before the failed run.
- `managed` setup maturity now requires a verifier and declared repair plan
  support in catalog validation.
