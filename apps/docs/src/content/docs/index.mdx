Avis is a source-available, ecosystem-agnostic CLI that safely adds, configures, and verifies common development capabilities inside existing software projects.

Framework scaffolders create the project. Avis equips it.

Avis is for the part after the starter template: the moment you realize a real app still needs auth, validation, forms, API tooling, monitoring, storage, email, caching, background jobs, and a dozen careful little setup steps you have done before.

```txt
$ npm install -g avis-dev@alpha
$ cd my-next-app
$ avis search icons

Search results for "icons":
- capability: icons (Icons) - Icon libraries and icon systems for application interfaces.
- integration: lucide-react (Lucide React) - A consistent, tree-shakeable outline icon system for React interfaces.

$ avis add icons

Detected:
Framework: nextjs
Language: typescript
Ecosystem: node
Package manager: pnpm

Recommendation:
Use lucide-react for icons.

Avis will make these changes:

Dependencies
+ lucide-react

Apply changes? Yes
OK Installed lucide-react.

Verification:
OK dependency installed
```

## Why Avis Exists

After `create-next-app`, `django-admin startproject`, `rails new`, `cargo new`, `dotnet new`, or another framework initializer, developers still repeat the same setup work: state management, data fetching, forms, validation, API tooling, testing, monitoring, storage, background jobs, and more.

Avis starts after project initialization. It detects the project you already have, lets you ask for a purpose such as `icons`, `validation`, or `state-management`, recommends compatible integrations, previews a ChangePlan, asks before applying changes, and then verifies the result.

The public path is capability-first. You do not need to know whether the right command is `avis add lucide-react`, `avis add react-icons`, or `avis add heroicons-react`; start with `avis add icons` and let Avis show the recommendation and alternatives.

## V3.1 Alpha Focus

V3.1 is a release-hardening pass. It introduces clearer setup maturity, stronger catalog validation, fixture-based QA, packaged CLI smoke testing, and safer repair behavior.

Avis now classifies integration support as:

- `install`: add a compatible dependency
- `configure`: add dependency plus useful starter files or configuration
- `managed`: verify setup health and generate supported repair plans

Repair is intentionally conservative. `avis repair` only runs where an integration declares repair-plan support, and it checks Avis' recorded file hashes before mutating managed files. If local edits make a repair ambiguous, Avis stops for manual review rather than overwriting user work.

## More Than Installation

`avis doctor` is a core part of Avis. A dependency being present is not enough to mark an integration healthy. For example, a Next.js project with `@tanstack/react-query` installed but no generated provider module is reported as partially configured.

The V3.1 release gate also tests the package as users receive it: Avis packs the npm artifact, installs the generated tarball into a clean temporary project, and exercises the installed `avis` binary before release.
